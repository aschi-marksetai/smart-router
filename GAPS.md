# Gaps versus native subagents

What a Claude Code `Agent` call or a Codex `spawn_agent` can do that `smart-router spawn` cannot, and what closing each gap would take. Updated as gaps close.

| Gap                                  | Native behavior                                                                                                                       | smart-router today                                                                                                                              | Bridge                                                                                                                                                                                                        | Effort                                             |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Fork with the parent's conversation  | Claude Code's fork subagent inherits the whole transcript                                                                             | The delegate sees only its prompt                                                                                                               | None. Only the caller can write the brief. Claude-only feature; Codex has no equivalent                                                                                                                       | Not bridgeable                                     |
| Parent-session MCP servers           | A native Claude subagent shares MCP servers and settings configured in the parent session, including ones added only for that session | A spawned claude gets the user's global config and the cwd project's config, not servers attached only to the parent session                    | `--mcp-config <file>` passthrough to claude, with the caller exporting its session servers. Codex delegates use their own config regardless                                                                   | Small, half a day, and only if a real case appears |
| Live progress in the caller's UI     | Native runs stream progress into the harness UI                                                                                       | Detached spawns write the harness's JSON event log; the caller polls `logs`                                                                     | A `--follow` on `logs` that tails the file and prints only agent messages. Rendering inside the caller's UI is not possible from a CLI                                                                        | Small, a couple of hours                           |
| Steering a running delegate          | Claude Code can message a running subagent                                                                                            | `send` waits for the session to finish; `stop` is the only mid-run action                                                                       | Codex has `codex queue --thread`, so a `queue` command is feasible for codex sessions. Claude print mode has no equivalent; steering would need stream-json input mode kept open, which is a different runner | Medium for codex, one day. Large for claude        |
| Agent definitions                    | Claude Code agents carry a fixed system prompt, tool list and model per agent type                                                    | Guardrails append prose per model; tool lists are per call                                                                                      | A named-profile section in config that bundles model, effort, permission mode, allowed tools and a guardrails key, selected with `--profile`                                                                  | Medium, one day                                    |
| Workflow orchestration               | Claude Code's Workflow tool scripts pipelines and fan-out with cached resume                                                          | One spawn per call; the caller fans out                                                                                                         | Nothing to build. Callers already have shell and their own orchestration tools                                                                                                                                | None                                               |
| Permission prompts reaching the user | A native Claude subagent's permission prompts surface to the user                                                                     | Spawned claude runs with the configured permission mode, bypass by default, and codex with a sandbox                                            | `--permission-mode` per spawn exists. Interactive prompts would require the delegate to run attached to the user's terminal, which defeats delegation                                                         | By design                                          |
| Codex calling smart-router           | Native Codex subagents run inside the sandbox                                                                                         | The Jev call and the spawned harness need network and process access, which the default Codex sandbox denies                                    | Run Codex with full access, or add a `--no-jev` fallback that skips routing and uses the default model when the network is unreachable. The fallback half already exists                                      | Small, if wanted                                   |
| Browser work on Codex delegates      | Native Codex sessions use the browser served by the ChatGPT app through the Codex Chrome extension                                    | Works from `codex exec` too, but only while the extension is connected; a stale extension makes every session report "Browser is not available" | Reload the Codex Chrome extension. When a task needs a browser the router already gives the Codex delegate full sandbox access. Claude delegates have their own isolated Chrome DevTools server as a fallback | Environment, not code                              |

Closed in this repo: background execution with status, logs, wait and stop; session ownership, listing and cleanup; usage and cost in every result; per-spawn permission mode, sandbox, allowed tools and output schema; the routing pick visible before the delegate starts.

## Gaps in smart-router itself

Not comparisons with native subagents, just things the current build does not do.

| Gap                                   | Today                                                                                             | Bridge                                                                                                                | Effort                             |
| ------------------------------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| Stopping-point check only when routed | `--model` skips routing, so a caller can hand Sol a prompt with no stopping point                 | Run the two Noul questions even on `--model` spawns, at one cheap Jev call                                            | Small, an hour                     |
| No timeout on a foreground spawn      | A hung delegate blocks the caller until killed                                                    | `--timeout <seconds>` that stops the child and returns an error                                                       | Small, an hour                     |
| No routing history                    | Each decision is printed once and lost; nothing shows how picks drift as preferences change       | Persist the route result in the session file and add `history` to summarise picks, confidence and fallbacks over time | Small, half a day                  |
| `send` is foreground only             | A long follow-up blocks the caller like a foreground spawn                                        | `send --detach` reusing the detached runner and the same status, wait and stop commands                               | Small, a couple of hours           |
| pi adapter never run                  | pi is not installed on the machine it was built on, so its event parsing is README-derived        | Install pi, run the existing adapter tests against real output, fix the parser                                        | Small, an hour, needs pi installed |
| Session logs are plaintext            | Prompts and results, which may include confidential material, sit readable in the state directory | Mode 0600 on log and session files, and `prune` above                                                                 | Small, an hour                     |
| Worktree flag unverified              | `--worktree` passes through to both harnesses but no test has run it                              | One live spawn per harness with the flag, check the worktree exists and the result comes back                         | Small, an hour                     |
| Jev outage only falls back            | A missing or invalid key silently uses the default model on every call                            | A `doctor` warning when the key is missing, and a counter in `history` of how often routing fell back                 | Small, an hour                     |
